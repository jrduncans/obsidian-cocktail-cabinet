# Development roadmap

Drafted on 2026-11-03 from a review of the plugin at `2d4462f` and of the cocktail workflows the `knowledge` vault uses today. It is written from the user's side: what each workflow needs before it can be called done, and the order that lets the plugin replace the vault's skills soonest. Phases and their contents are a plan, not approved implementation scope; record decisions in [the cabinet design](cabinet-design.md). Phase 1 was revised and agreed on 2026-11-03; see [adoption and logging decisions](cabinet-design.md#adoption-and-logging-decisions). Updated on 2026-11-04 with friction found testing logging in the dev vault: editing, browsing, and the starter's lack of examples.

## Phases

### 1. Move in: unblock real use and retire `cocktail-inventory-update`

Drink logging must work on the day the `knowledge` vault switches over; bridging the current fraction-based skill is not worth it.

1. **Classification mapping.** One table, approved before any vault write: each old note's new type, family, and filename. It settles the twelve bottle-level decisions and every recipe link whose meaning changes (Falernum, the old Amaro and Other Herbal Liqueur catch-alls, cacao color, syrup concentration, the generic Coconut Rum requirement, FALSE IDOL's Navy Strength). Anything the starter does not cover becomes a local type under an existing starter family where one fits.
2. **Log this cocktail.** A command on the recipe note: servings, a bottle-review screen, mL preview with rollover into unopened bottles, all-or-nothing apply on shortfall, and the daily-note line. Implemented on desktop with measured other-stock sources, explicit alternatives, stale-preview checks, and native Daily notes templates. Operation-level retry protection remains Phase 2; see the decisions for the review screen.
3. **Migration script.** Implemented and rehearsed in the dev vault; see [usage and safeguards](knowledge-migration.md). Reuses plugin code, reports every planned operation and unresolved item, rewrites ingredient links, and generates navigation and shopping views. Rehearsal apply to the personal `knowledge` vault is forbidden; cutover uses the in-place mode (step 7).
4. **Finish the starter first.** Pulled forward from Phase 2 on 2026-11-04, because the migration adds every starter note the vault lacks. Built: the worked example (new cabinets only, stock Unknown), the "House <type>" default name, and **Add a bottle of this type** / **Add other stock for this type**; see [homemade stock](cabinet-design.md#homemade-stock). The dev vault's syrup types use the ratio names, and its syrup stock became House Simple Syrup (1:1). Step 5 decides which examples the migration adds.
5. **Migration handles the example.** Built 2026-11-04: the migration adds each starter example unless the vault has a recipe of the same name or other stock providing the same type, and reports the skips. For `knowledge` all five are skipped (Fresh Limes, Fresh Lemons, the House syrup, Daiquiri, Whiskey Sour). Rehearsed into the dev vault's `Knowledge rehearsal 2` with no conversion errors.
6. **Rename pre-pass.** Done 2026-11-04 in three `knowledge` commits: display text and aliases, 31 filename-only renames, then 12 type renames, Fruit Juice → Juice, and the House syrup names (46 renames). The migration reads renamed notes under their old names, and its plan was verified identical after each pass. See [the pre-pass](knowledge-migration.md#rename-pre-pass). Originally: before cutover, rename notes in `knowledge` through Obsidian (which updates links everywhere, including daily notes) for filename-only and one-to-one renames: accent folds, `#2` → `No 2`, `V.S.` → `VS`, `ø` → `oe`, one-to-one type renames, and the House syrup names. First give each link to a renamed note explicit display text, so wording is kept (`[[Vieux Carre|Vieux Carré]]`); approved for daily notes. Reclassifications, merges, retirements, subcategories → families, and `cc-` properties stay in the migration, which must accept notes that already have their new names. Run in passes, reviewing a `git diff` of `knowledge` after each. See [before cutover](knowledge-migration.md#before-cutover).
7. **Cutover.** Applied to `knowledge` on 2026-11-04. The plugin installs there with `npm run install:vault` from `main`. `migrate:knowledge --in-place` was built for it; see [cutover in place](knowledge-migration.md#cutover-in-place). Done: `cocktail-inventory-update`, the old Bases, the templates, and the old DataviewJS views are retired, and the vault's `AGENTS.md` describes the cabinet schema and marks the query and import skills outdated. Other breakage (the query and import skills, the DataviewJS views) is fixed as it is hit.

Steps 1 and 2 are independent; step 3 needs step 1's table. Steps 4 through 7 run in order.

Not in this phase: stock-editing actions and renaming (Phase 2), and a general adoption flow (at most building blocks, if ever).

### 2. Live in it: browse and edit without hand edits

Found while testing logging on 2026-11-04. Order within the phase is open. Navigation was built first, because cutover breaks the vault's DataviewJS navigation.

- Built: hierarchy navigation embedded in category, family, type, bottle, and other-stock notes through a shared core Base; see [navigation in notes](cabinet-design.md#navigation-in-notes). The migration script must add the embeds to adopted notes.
- Built: **Rename cabinet note**, keeping file name, H1, `cc-name`, aliases, and links in step; see [renaming](cabinet-design.md#renaming). Tested on desktop in the dev vault; mobile not yet checked.
- Built: **Edit stock** on a bottle or other stock: Bought more, Finished, set the level, price and shopping flag, and switch tracking mode with an explicit conversion (mL to availability keeps nothing numeric; availability to mL asks for the amounts). No Open next bottle action: logging opens a sealed bottle when needed. See [editing stock](cabinet-design.md#editing-stock). On mobile it works, but the keyboard covers much of the form and Save is below the fold; a shared mobile pass on the cabinet forms belongs with the logging mobile pass in Phase 3.
- Built: the **Shopping list** note, with sections for flagged bottles, types, and other stock; see [purchasing and the shopping list](note-properties.md#purchasing-and-the-shopping-list).
- Built: **Edit cabinet note**, the creation form's fields for an existing note apart from name and stock, rewriting only the recipe sections that changed; see [editing notes](cabinet-design.md#editing-notes). Tested on desktop in the dev vault; mobile not yet checked. It also covers relinking plain-text recipe ingredients and adds a rating input, both earlier listed under Phase 4.
- Built in Phase 1, step 4: **Add stock for this type**, the "House <type>" default name, and the starter's worked example.

### 3. Harden logging

- New: each logging operation identified so retries and partial failures are recoverable.
- Finish: a mobile test pass.

### 4. Everyday polish: less command-hunting

- Finish: recipe review adds tags and rating, and warns about duplicates. Relinking and rating existing recipes are covered by **Edit cabinet note**.
- Built 2026-11-06: a header button for each note's main action (**Log this cocktail** on recipes, **Edit stock** on bottles and other stock), every note command in the file menu and the note's More options menu, so mobile doesn't need the command palette, and a **Latest** view in `Recipes.base`. **Browse related recipes** was removed; the in-note Recipes sections replace it.
- Built 2026-11-06: fix stock as you go. The logging modal opens **Edit stock** for a source that's short, and from each Stock row; the **Restock** Base lists stock running low, out, and unknown (availability Unknown or no tracking mode), each with a shopping-list checkbox. A check date was tried and dropped the same day, and blank amounts now mean 0 rather than unknown. See [editing stock](cabinet-design.md#editing-stock).
- Built 2026-11-06: the plugin owns the Bases in `Views/` and keeps them current (on startup when a release or setting changes one, or with **Refresh cabinet views**); users keep their own in `Custom views/`. Restock's running-low thresholds are settings (default 10% and 70 mL).
- Built 2026-11-06: logging records `cc-last-used` on bottles and other stock, and `cc-last-made` and `cc-times-made` on recipes. Restock's Running low and Out sort by last used; `Recipes.base` has a **Recently made** view. File modified dates were tried for Restock's order and dropped: sync and Git make them unreliable. Possible next: a neglected-bottles view (in stock, least recently used).
- Built 2026-11-06: **Record purchases**, recording a shopping trip from the Shopping list (and anything bought off it, including new bottles), with price, size changes, and `cc-last-purchased`. See [recording purchases](cabinet-design.md#recording-purchases).
- New, from a 2026-11-06 UX review (not yet designed in detail):
    - Built 2026-11-06: Recipes sections grouped into recipes that call for the note above recipes it can fill through something broader, and [catch-all types](cabinet-design.md#catch-all-types) (`cc-catch-all`), whose bottles are offered as likely substitutes but never assumed.
    - Built 2026-11-06: [unlinked measured lines](cabinet-design.md#unlinked-lines) get **Link…** in the logging modal, and **Review unlinked ingredients** links a wording across recipes. (Its **Keep as text** was removed 2026-11-07.)
    - Built 2026-11-07: a [link text](cabinet-design.md#unlinked-lines) choice wherever a line is linked, and the editor commands **Insert ingredient link**, **Link this ingredient line**, and **Edit this ingredient link**. Next: the review as a side pane that opens each recipe beside it; tidying short links like `[[Gin]]`; friendlier create and enhance recipe forms.
- New, designed 2026-11-08: [kitchen staples](cabinet-design.md#kitchen-staples), so everyday ingredients take one note and one step.
    - Built 2026-11-09: **Add kitchen staple**, the `Kitchen staple` form, and hiding Provides for it. A blank Provides checked out in the Bases and the shopping list.
    - Built 2026-11-09: starter staples at Unknown, Saline Solution among them, and an Eggs note providing Whole Egg and Egg White. Soda Water and Cocktail Cherry stay types.
    - Built 2026-11-09: **Browse** in Ingredient types, **Kitchen staples** in Other stock, a new **In stock** view, staples out of Restock's Unknown tab, and the cabinet home's new section and "start here" order. Verified with desktop dev-vault Bases queries; existing homes need the [documented hand edit](cabinet-design.md#kitchen-staples). Mobile layout not yet checked.
    - Built 2026-11-09: **Review unlinked ingredients** also covers unmeasured lines matching any ingredient note's name or alias, with marked garnishes hidden by default and a **Show garnishes** toggle. Logging still leaves unmeasured lines unsubtracted.
    - Not built: Convert Salt, Mint, Heavy Cream, and Milk in `knowledge`, and add its Eggs note, once this release is installed there.

### 5. Reach: retire the remaining skills

- New: Bevnap CSV and web-page recipe import, following the source-fidelity rules of `cocktail-recipe-import`.
- New: availability queries (what can I make, what am I missing).
- New: agent integration through a CLI handler; publication remains a separate decision.
